TTFT vs Throughput (A10G only — H100 vLLM path does not expose TTFT)

TTFT = Time to First Token — latency until the model starts streaming output (prefill phase only). Each point is one quantization mode. Lower-left = faster first token AND higher throughput.

MMLU Accuracy + Perplexity (HF modes only)

MMLU scores on a 50-question CS/ML-domain subset (not the full benchmark; published general MMLU ≈66–68%). Scores cluster 74–94% — quantization barely affects accuracy at 4–8 bit. Perplexity (lower = better) reveals subtle degradation: nf4 and gptq add ~0.2 ppl vs fp16.

Batch Scaling — Output tok/s at batch 1 / 4 / 8

Memory-bandwidth bound: All 8B inference on these GPUs at batch ≤ 8 is memory-bandwidth-bound (purple in MFU charts). The bottleneck is loading model weights from HBM on every decode step — not attention. H100's HBM3 (3.35 TB/s vs A10G's 0.60 TB/s) explains the 8x throughput difference at nearly identical MFU%.
Energy Efficiency — Tokens per Joule

Measured via nvidia-smi power polling during inference. Purple bars = size-sweep configs; blue = standard 8B modes. Higher tokens/joule = more compute per watt.

Tokens / Joule + Mean Power Draw (W) (modes with power data only)

3B-fp16 leads at 0.32 tok/J — smaller weights load faster per decode step, spending less energy per token. GPTQ (0.27) is the most efficient full 8B mode: INT4 weights halve bandwidth pressure vs fp16.

Throughput (req/s) vs Concurrency

Limitation of fixed-concurrency testing: semaphore-based load never reveals true queuing behaviour — request N+1 only starts when one slot frees. See Poisson arrivals below for the queuing saturation curve.

P50 + P99 Latency vs Achieved Throughput (log Y)

Saturation knee at λ≈2.0 rps: P50 stays flat while P99 explodes — the classic M/M/1 queuing signature. Fixed-concurrency tests miss this entirely because they throttle arrival rate. Beyond the knee, adding more load only increases queue depth and tail latency, not throughput.

Kernel Category Breakdown — % of GPU time (fp16 · int8 · nf4)

Click legend items to hide/show categories — y-axis auto-adjusts so you can inspect smaller categories (attention, dequantize) after hiding the dominant matmul.

Attention is only ~1% of GPU time on 8B models at short context — matmul (weight loading) dominates at 44-58%. This confirms memory-bandwidth as the binding constraint, not attention complexity. int8/nf4 add dequantize kernels absent in fp16 — the overhead of converting compressed weights back to float16 before compute explains why quantization doesn't linearly reduce latency despite halving VRAM.
